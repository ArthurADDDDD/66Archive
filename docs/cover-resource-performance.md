# 封面资源加载与回归检查

## 问题与处理

本地封面已经有 AVIF / WebP 派生图，但游戏厅、游戏预告卡、录播室网格与栏目横向封面只通过远程图片代理生成 `srcset`。代理对站内路径直接返回原图，所以这些入口仍然下载 JPEG。

`src/components/ResponsiveCover.tsx` 统一封面的图片输出：

- 本地条目封面、周年作品、画廊缩略图使用现有的 360 / 720 档 AVIF → WebP → 原图；
- 远程封面保留原有代理策略和调用方指定的宽度；
- 未知路径或没有响应式尺寸的调用保持原图，不猜测派生文件名；
- `loading`、`fetchPriority`、替代文字、样式和错误处理仍由调用方控制。

列表封面维持懒加载；条目页封面维持高优先级。图片格式与尺寸由浏览器选择，不等客户端挂载后才替换地址。原理见 [MDN 响应式图片](https://developer.mozilla.org/en-US/docs/Web/HTML/Guides/Responsive_images)。

游戏详情页的大封面例外：高 DPR 下需要 840–960px，而现有本地派生图最大只有 720px。这些位置以 `data-cover-original="full-size"` 明确保留原图，避免用体积收益换取清晰度下降。不要把这个标记用于普通缩略图。

## 2026-10-15 自检记录

未限制网络和 CPU 的线上 Chromium 单次采样：首页 LCP 812ms，游戏厅 LCP 503ms，CLS 均为 0。请求可能命中缓存，不代表冷启动、低端手机或真实用户分布；没有据此宣称页面提速百分比。

现有 153 张本地条目封面的文件体积合计：

| 格式 | 字节 | 相比 JPEG |
| --- | ---: | ---: |
| 原始 JPEG | 9,637,725 | — |
| 360px AVIF | 1,248,181 | 减少 87.0% |
| 720px AVIF | 2,866,146 | 减少 70.3% |

这是整批资源的体积，不是单次页面访问的下载量。优化复用已有派生文件，没有新增图片或更改档案记录。

游戏厅默认列表中的两张本地封面（2015-09-09、2010-07-11）可直接复测：原图合计 151,284 字节，360px AVIF 合计 18,063 字节（减少 88.1%），720px AVIF 合计 36,976 字节（减少 75.6%）。桌面 1280px / DPR 1 的浏览器实际选中 360px AVIF，图片框宽约 211px，加载正常。手机模拟 390px / DPR 2 也选中 360px AVIF，无水平溢出；已查看桌面和手机截图。DPR 3 冷加载、Safari 和真实手机尚未验证。

最终导出检查扫描了 3,805 个 HTML 文件，其中 210 页包含本地封面，未发现未声明的原图封面或缺失候选。旧导出产物的 168 处原图引用中，151 处已接入现代格式，17 处保留为大封面高清例外。

## 检查方法

```bash
npm run test:covers
CONTENT_BAKE_ORIGIN=off npm run build
npm run audit:covers
# 输出每页去重后的本地封面文件大小，便于比较；不是网络传输量或时序指标。
python3 scripts/audit-cover-resources.py --json
```

`test:covers` 检查组件的静态输出、远程代理兼容、加载属性，以及所有条目封面和周年作品的四份派生文件。检查器自身的用例覆盖原图遗漏、候选文件缺失、缺少 `sizes`、固定画质档位与高清例外。

`audit:covers` 扫描导出 HTML，拦截没有声明高清用途的本地原图封面、丢失的本地候选文件，以及缺少 `sizes` 的宽度候选。画廊主动选择的固定画质档位合法。校验流水线会在构建后运行这两项。

覆盖范围限于静态 HTML 中的本地封面。客户端筛选后才出现的内容、远程图片可用性、真实手机解码与弱网体验仍需浏览器验证；灯箱原图、视频和 CSS 背景图不属于这个缩略图检查器。
