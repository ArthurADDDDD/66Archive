# 开播提醒入口

首页「关于她」旁的「开播提醒」按钮打开邮箱弹窗。用户填写邮箱并主动勾选接收意愿，再申请确认邮件；只有邮件接口明确返回需要确认邮箱，才展示「还差一步，确认邮箱」。前端不把接口受理当成订阅已激活。

确认与退订接口、操作页面和隐私说明已实现，尚未公开启用。弹窗读取可用性；服务不可用或未开放时明确提示准备中、禁止提交，不保存邮箱。未提交的填写内容仅在当前弹窗的内存中，关闭后清除，不写 localStorage、URL 或分析事件。实际提交时邮箱才交给订阅服务。不会因为部署前端改动自动产生订阅名单。

## 公开接口预留契约

前端请求同域接口；本地联调可通过现有 `NEXT_PUBLIC_CONTENT_ORIGIN` 指定内容服务公开地址。

- `GET /api/live-alerts/subscriptions`：`{"enabled":true}` 才允许提交；关闭时返回 `{"enabled":false}`。响应不得缓存过期的开放状态。
- `POST /api/live-alerts/subscriptions`：JSON 请求体为 `{"email":"you@example.com","consent":true}`。
- 确认邮件请求已接收后返回 202 与 `{"status":"confirmation_required"}`，发送可能稍晚。这不表示邮箱已验证；同一邮箱重复请求保持统一响应，避免暴露邮箱是否已存在。
- 400：邮箱格式或接收意愿不符合要求；429：请求过频；服务未配置/关闭、网络异常或响应不符合契约时不得显示成功。
- POST 超时或响应无法确认时，提示先检查确认邮件，不声称肯定没有发送。

真正开放接口前，必须完成邮箱确认、可用退订链接、隐私说明、服务端防滥用/限流、订阅存储、重复请求处理，以及邮件额度/发送记录的衔接。未完成这些步骤时保持 `enabled:false`。

确认链接落在 `/live-alerts/confirm/`，退订链接落在 `/live-alerts/unsubscribe/`。链接中的令牌放在 URL fragment，页面读取后立即从地址栏移除；用户点击按钮后才通过 JSON POST 请求 `/api/live-alerts/confirm` 或 `/api/live-alerts/unsubscribe`，仅打开链接不产生写入。确认成功返回 `{"status":"confirmed"}`，退订成功返回 `{"status":"unsubscribed"}`。操作页面不进入 sitemap，设置 noindex 与 no-referrer；不展示收件邮箱。

`/privacy/` 说明收集目的、第三方发信处理、保留时间、退订与联系路径。首页勾选接收意愿前可打开说明；网站页脚也有入口。

## 自检

2026-10-12 浏览器检查：按钮打开弹窗、输入焦点、无效邮箱校验、主动勾选、接口未开放时禁止提交、模拟确认邮件响应、快速重复提交只发一次请求、Esc 关闭并恢复按钮焦点与页面滚动。模拟请求未发送真实邮件。桌面与手机尺寸另做布局检查；这些不代替真实订阅服务验收。

确认/退订页面还检查了：读取后清除 fragment、只在点击后 POST、确认按钮快速重复点击只发一个请求、成功提示。真实邮件投递与线上启用仍需单独验收。
