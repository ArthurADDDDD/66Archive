# 实时内容的请求复用与渐进更新

前台按路由读取站点文案、叙事和编排分片。烤入内容仍负责首屏与接口失败时的兜底，稳定 id 和覆盖规则不变。

此前 Provider 把发出的请求永久标记为已请求，并在路由需求变化时取消旧响应的处理。请求尚未完成就切页，会使新页面既不接收旧响应，也不重新请求。首页的三份响应还必须全部完成后才一起更新，一份慢响应会延迟其他已到达的内容。

现在每个 Provider 使用独立的分片请求缓存：

- 进行中的请求由新订阅复用，切页只取消旧页面的订阅，不丢弃网络结果。
- 每份响应单独更新对应内容，不等待其他分片。
- 成功响应在本次 Provider 生命周期内复用，站内往返不重复下载。
- 失败或无效响应不长期缓存；下一次切页可以重新请求，底层仍沿用既有超时和有限退避重试。
- 失败不会覆盖烤入内容，也不会把未到达的站点文案标记为已到达。
- 卸载后不更新组件状态；开发模式 effect 清理与重建也复用同一份请求。

该缓存不跨访客、不跨服务端请求，也没有新增轮询、接口或存储。刷新页面会建立新的 Provider，正常读取当前内容。

运行 `npm run test:live-content` 可检查快速切页、独立到达、失败恢复、成功缓存复用、取消订阅与 effect 重建；校验流水线会运行这项检查。收益主要是减少无效等待、避免丢弃已下载响应，不以此声称固定的加载时间改善。
