# 录播室载荷加载与恢复

录播室先呈现构建期目录，再加载完整档案。首屏脚本与客户端共享带版本号的
`dataUrl`，请求缓存只保留最近一个版本，不修改正式数据或载荷编码格式。

## 本轮审查发现及修复

- 预取原来只有 Promise，没有 URL 身份：客户端无法判断它是不是当前版本。
  现在预取记录 `{ url, promise }`，仅在 URL 一致时接手。无身份的旧预取会被忽略，
  客户端重新请求当前 URL；不是对响应内容版本作密码学验证。
- 已经显示过数据的组件切换 `dataUrl` 后，旧数据会遮住新请求的失败状态。
  现在按 URL 重建加载状态，旧版本的响应无法更新新版本视图。
- HTTP/JSON 失败原来可以重试，但一直没有完成的请求没有退出路径。
  现在每次网络请求（包括读完响应体）最多等待 60 秒，超时中止传输。
  预取失败后允许一次正常请求，所以从预取开始到最终失败最多可能经历两个请求窗口。
- 预取内容可以解析但解码失败时，原来直接进入错误页。
  现在先尝试正常请求；正常请求仍失败才显示已有的错误与重试入口。

相同 URL 的并发消费者共享请求，成功结果复用；失败清除对应 Promise。
旧请求晚到的失败不能清掉新版本缓存。离开页面只取消视图更新，不取消共享请求，
避免来回导航重复下载；超时仍会回收未完成的网络请求。

## 自检

- `npm run test:archive-loader`：预取身份、共享请求、格式错误、HTTP 错误、重试、
  旧请求竞态、超时和实际生成的首屏脚本。
- `npm run test:archive-payload`：真实档案编码往返与上一版格式兼容。
- `CONTENT_BAKE_ORIGIN=off npm run build`：包含数据校验、类型检查与静态导出。

60 秒是故障恢复上限，不是加载速度承诺。此改动不改变 CDN 缓存策略，
也不代替真实网络下的性能测量。外部来源是否有效、档案内容是否准确须另行复核。

本轮本地静态产物的浏览器自检：带搜索参数进入录播室时只请求一次档案载荷，
搜索状态恢复；模拟首屏预取及后续请求均返回 503 时显示失败提示，点击重试后
第三次请求成功，原搜索条件与结果恢复。未实测生产网络、移动设备或真实连续部署；
版本竞态与超时由自动化测试覆盖。
