# 2020–2023 source metadata batch review (2026-10-22)

本批次针对既有 `middle.csv` 中备注指出覆盖缺口、分段、不同直播间或标题冲突的候选，选取 B 站非官方稿件进行公开页面元数据核验。范围是 API 返回的投稿标题、UP 主显示名、分 P 标题与时长；没有下载或播放视频，也没有验证画面内容、录制连续性或直播日期归属。CSV 按来源列出结果，可复核每条页面。

## 覆盖与方法

- 输入范围为 2020-01-01 至 2023-12-31 的既有清查表；此处选了 19 条来源记录、17 个不同 BVID，其中聚合稿 BV1qt411c7xR 对应 4 个场次的指定分 P。
- B 站公开页面接口：[`/x/web-interface/view`](https://api.bilibili.com/x/web-interface/view?bvid=BV1vV4y1b7rG)，以普通浏览器 User-Agent 和站点 Referer 请求。一次请求返回 TLS EOF（BV1X54y1e7Pi），未重试或绕过。其余 16 个 BVID 返回元数据。
- 这只是页面元数据核对；不能据标题、时间戳、分 P 数或总时长宣称已看过视频、确认画面游戏、证明全场覆盖或排除遗漏。B 站显示名“账号已注销”也只代表当前 API 显示状态，不反推历史账号身份。

## 结果

- 明确非完整/部分覆盖证据：2020-03-19 标题明写“只有一半”，接口返回 4P、3:04:04，对比档案 502 分钟；2020-03-20、03-30、05-13 页面时长低于对应档案时长，且 05-13 的分 P 时间标识在约 17:06 与 18:53 间有明显间隔。它们与档案已有备注相符，没有出现新的“其实是完整录像”证据。
- 分 P 指向相同日期和场次、但场次映射未决：2020-01-04 秘密录像屋稿件确有 5P、1:52:26；仓储员聚合稿 P285–287 标有 16:05–17:01，合计 1:14:53。页面时间戳支持这些片段确实跨越所标时段，却不能确认它们分别对应斗鱼 14:00 或 16:00 场，也不能据此填补场次归属。
- 分段而非整日覆盖：2022-08-03 两条自动录制的公开元数据分别为 2:45:12（15:32:37）与 0:31:16（19:54:47），合计 3:16:28；与档案备注里的 1:36:58 空档一致。2022-11-16 两个单 P 分别 1:59:14、1:32:24，合计 3:31:38；它们不能独立代表档案记载的 441 分钟日跨度。
- 已有独立来源说明被 API 标题进一步支持：2020-06-06 的一条稿件是“女流录像小屋”4P、4:03:48；另一条不同上传者的稿件标题明确为 Sylvia 访谈，2P、2:17:08。元数据与档案所述“访谈录而非女流本人整场回放”相符。
- 新增明确标题字段冲突证据：2023-07-15 BV1vV4y1b7rG 的投稿总标题写“街霸6”，但分 P 标题写“永劫无间”；另一条 KassyTan 投稿为 9P、4:43:22，日期和时长接近档案记载，分 P 名只有日期/时间。API 结果解释了现存冲突所在字段，但不证明画面实际内容，因此游戏归属仍 unresolved。
- 其余日期/单 P 元数据与已收录说明相符或不足以判断内容：2020-01-17、2020-06-09、2023-06-16、2023-05-03。标题/时间信息不能替代画面验证。2020-09-04 请求受阻，完全未核实。

## 结论边界

本次没有发现可凭元数据直接判定“错场”或“实际画面游戏错误”的新证据。发现/确认的风险仍集中在：已有注记明确的短于日跨度的补充片段、上传标题字段冲突、以及仅有录制时间戳而缺乏画面证据的来源。优先级应是继续核实 BV1vV4y1b7rG 的分 P 内容/档案关联，以及 2020-01-04 仓储员片段和两场直播的对应关系；单靠接口元数据无法完成这两项。
