# 游戏精准定位产品集成

已审阅时间轴从 `data/game-timelines.yaml` 加载，生产构建无需本地预览输入。统计口径以 [游戏环节时长定义](../../game-time.md) 为准。

游戏页按日期列出每一段游戏区间，同场回切保留独立入口。录像页和共享展开卡显示游戏章节、独立环节、计时基准及核实状态。B站按快照分P和页内时间跳转；AcFun只支持分P，页内时间供手动定位。切换备选录像不会改变章节链接的基准来源。

游戏厅、首页与统计页使用统一的三档时长计算：已核实、关联录像和未知。录像总长度继续作为录像长度展示，不冒充游戏游玩时长。全站核实总量按实际区间累计一次，避免系列父条目重复计数。手机卡片同时显示核实量和归属覆盖。

首批12场游戏环节合计53:18:58，其中51:50:28满足已核实条件；独立环节5:47:36。一段1:28:30的游戏区间缺少内部检查记录，继续只计关联录像。没有补填人工审核字段。

机器候选保存在正式档案之外，未批准的结果不进入页面或已核实时长。后续新增时间轴须保留证据、人工批准和分P快照校验。

## 验证入口

- `npm run validate`：Schema、引用及时间守恒。
- `npm run test:game-time`：统一计时口径与平台跳转。
- `npm run test:game-chapters`：回切章节、公开投影及预览输入保护。
- `npm run test:archive-payload`：新旧档案载荷兼容。
- `CONTENT_BAKE_ORIGIN=off npm run build`：本地完整静态构建；资源受限时加 `ARCHIVE_BUILD_CHECK=1` 限为单worker。

生产候选仍遵循既有冻结内容、不可变产物和签名验证链路；合并代码不等于生产部署。发布产物就绪后由维护者在控制台确认部署。
