# 链接预取的统一预算

所有站内链接保持 `prefetch={false}`。根布局的 `RouteIntentPrefetch` 通过事件委托处理页头、浮动导航与正文，不再由各导航组件另外调用 `router.prefetch`。

行为约定：

- 鼠标悬停或键盘聚焦 100ms 后预取；从同一链接的图片移到文字不重新计时。
- 主指针按下时立即预取；不为中键或带修饰键的按下额外预取。
- 鼠标或焦点离开目标时取消等待；切页时清理旧计时器并建立新预算。
- 每页最多预取 12 个不同目标，导航与正文共同计数。
- 查询串与锚点不改变本站静态路由载荷，预取时去掉；当前页、外链、下载和新窗口链接不预取。
- 同步调用失败不占住名额。预取只是提前量，实际点击导航照常工作。

此前页头和浮动导航各有独立的计时器与去重表，全站委托又处理相同事件，导致重复调用且导航不受统一预算约束。Next 可能合并重复网络请求，因此不能把减少的函数调用数直接当作节省的下载字节。

`npm run test:route-prefetch` 使用可控计时器检查目标筛选、悬停延时、取消、同目标去重、预算及新页面预算重建；CI 会运行该检查。浏览器检查应同时确认普通链接仍能导航，而不是只统计预取请求。

本轮 Chromium 静态产物自检：快速移出链接与聚焦后立即离开均未发出预取请求；同一链接连续悬停、按下、聚焦只观察到一次路由载荷请求，点击后正常进入数据页。此结果验证调度行为，不是弱网提速或流量节省的对照实验。
