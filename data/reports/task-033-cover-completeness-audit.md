# Task 033：无封面 / 黑屏封面全库排查

> 触发：用户在 Task 032（多日期合集封面误导）之后，进一步要求排查全库范围内
> 「完全没有封面」和「封面是黑屏/加载图」这两类问题，处理方式与 Task 032 一致
> （必要时手动截图，不受「只索引不搬运」默认限制约束）。

## 第一部分：完全没有封面的条目（已完成）

### 问题

展示层的封面兜底逻辑（`src/lib/bilibili.ts` 的 `getBilibiliVideoMeta`）只对
`bilibili.com` 的来源生效。斗鱼官方回放（`v.douyu.com`）、YouTube、AcFun 来源
如果条目本身没有写 `cover`，页面上会一直显示「封面待补」占位——不是画面有问题，
是压根没有触发任何取图逻辑。

全库排查（条目本身无 `cover`、来源也都没有 `cover`、且没有存活的 B 站来源）
命中 **159 条**，全部集中在纯斗鱼官方回放 / YouTube / AcFun 来源的条目上。

### 处理方式

这批条目其实都有平台自己的官方封面，只是当初入库时没有抓：

- **斗鱼**（153 条）：`v.douyu.com/show/<vid>` 页面内嵌的 `window.$DATA` 里有
  `"pic"` 字段，是这条回放专属的封面图（不是像 Task 032 里 B 站那种整条投稿共用
  一张图的问题），直接可用。
- **YouTube**（4 条）：用官方 oEmbed 接口
  （`https://www.youtube.com/oembed?url=...&format=json`）拿 `thumbnail_url`。
- **AcFun**（2 条）：页面内嵌 JS 里的 `"coverUrl"` 字段。

流程：抓取 → 校验返回的确实是图片而不是错误页（个别 URL 虽然还留在页面数据里，
但 CDN 上文件已经 404，会返回一个「你想要的还不存在」的 HTML 提示页，必须过滤掉）
→ 用与第二部分相同的黑屏检测（详见下）确认不是黑屏 → 直接以外链形式写回条目的
`cover` 字段（不下载本地化，因为是平台自己对这条内容的官方封面，不是要替换掉
一张误导性的共享封面）。

**结果：159/159 全部找到有效封面，0 条黑屏，0 条死链，已全部写回。**

## 第二部分：已有封面里的黑屏 / 加载图排查（进行中）

### 范围

除了上面 159 条，全库还有：
- **2283 条**：条目或来源已经写了显式 `cover`（远程 URL，非本站 `/images/covers/`
  本地图）；
- **215 条**：没写显式 `cover`，但有存活的 B 站来源，靠 `getBilibiliVideoMeta`
  在客户端动态取整条投稿的官方封面。

这两类此前从未做过内容层面的检查——只确认过链接能不能打开，没检查画面是不是
黑屏、加载条、纯色占位图这类「技术上是张图，但没有信息量」的坏图。

### 检测方法

下载图片，缩到 64×36 灰度后计算均值和标准差；均值和标准差都很低（`mean < 14`
且 `std < 10`）判定为「大概率黑屏/纯色」——用标准差过滤是为了避免把画面本身
就偏暗但仍有内容（比如夜晚场景、暗色 UI）的正常封面误判掉。

### 结果：全库基本干净，无需批量重截

实际扫描覆盖 **2657 条**（比预估的 2498 多，因为部分条目同时命中「远程封面」
和「B 站自动兜底」两类判定口径，取并集后去重更完整）。命中情况：

- **1 条误报**：`2021-10-21-live-01`（AcFun 封面，均值 2.7 / 标准差 8.2）。
  人工核实是《Impostor Factory / 影子工厂》的游戏标题画面——黑色背景配灰白/
  金色文字，风格本身就偏暗，不是加载图或空白帧，画面本身能清楚认出游戏，
  不需要处理。这也说明纯亮度阈值会把「暗色调但有内容」和「真的是空白/加载图」
  混在一起，需要人工过一眼确认，不能只看数字。
- **1 条网络瞬时错误**：`2018-02-02-live-01`（`IncompleteRead`，读取中断），
  重试后正常拿到封面，均值 108.6，明显不是黑屏，只是这一轮扫描时网络抖动。

**结论：除了 Task 032 处理过程中已经手动修正的 `2016-04-20-live-01`
（截帧撞上加载黑屏，已换时间点重截），全库目前没有发现其它黑屏/空白封面。**
不需要针对第二部分再做批量重新截图。
