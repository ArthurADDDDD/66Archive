## 一、它们为什么一直没被发现

不是因为失效，而是因为**没人能浏览到**：`data/accounts.yaml` 的 `youku-official` 已记录，
`i.youku.com/nvliu66` 现在 302 跳到新主页系统，显示 **0 视频 0 粉丝**。
也就是说优酷官方空间对外完全是空的——视频本身还在，但除非你已经知道 vid，
否则没有任何入口能走到它。

所以补档的关键不是「找回文件」，而是**把 vid 找出来**。

## 二、vid 是怎么找出来的

互联网档案馆存有 `i.youku.com/nvliu66` 的 **2014-10-30** 抓取
（`20141030085922`，是该 URL 唯一一次有效抓取，其余全是风控页）。
该页列出 28 个 vid，逐一比对 `data/entries/` 与 `youku-video-era.csv` 之后，
有 2 个两边都没有——就是上面前两条。

第三条不同：它在 `youku-video-era.csv` 里早有一行，但 date 字段是
`07-16 20:52`（缺年份，与其余 80 行的 `YYYY-MM-DD` 格式不一致），
所以一直没人能把它导进条目。

## 三、日期是怎么定的：两条路互相印证

### 先用 vid 定序卡出区间

优酷 vid 是 `"X" + base64(纯数字 id)`：

    XMTcxMzcyMjAw → 171372200 → 2010-05-08（首条视频《迷画之塔》）
    XODc4ODk2NTY4 → 878896568 → 2015-01-24

这个数字 id 随上传时间单调递增。**在本仓 80 条已定日期的优酷条目上实测：
79 对相邻样本全部顺序一致，0 处逆序。** 用相邻锚点做线性内插，三条分别落在
2013-07-16、2010-05-18、2010-06-05。

### 再用详情页取原始记载

随后发现这三条的优酷页面**至今仍然在线**，页面里直接带 `publishTime`：

| 条目 | 内插预测 | 页面 publishTime | 时长 |
|---|---|---|---|
| 大叔的末日骑行 | 2013-07-16 | **2013-07-16 20:52:11** | PT14M13.70S |
| 十大雷人小游戏排行榜 | 2010-05-18 | **2010-05-18 16:57:20** | PT20M36.93S |
| 超级玛丽…各种遭遇 | 2010-06-05 | **2010-06-05 23:26:56** | PT8M53.13S |

**三条内插全部命中到日。** 第一条的 `20:52` 还与目录里当初抓到的
「07-16 20:52」吻合到分钟。

入库用的是 `publishTime` 这个原始记载，不是内插值；内插只是先导出了同样的答案，
反过来成了对这套定序方法的一次预测性验证——**以后再遇到没有日期的优酷素材，
这个梯子可以先用来卡区间**。`duration_min` 按全仓既有惯例取 `round(秒/60)`
（在 8 条同时有目录时长与条目时长的样本上核对过，8/8 一致）。

## 四、顺带确认：目录的 `alive` 列已经不可信

`youku-video-era.csv` 把 81 行里的 53 行标成 `alive=N`，而 `data/entries/` 里
对应的 source 全部是 `alive`——**52 处直接冲突**。实测两条（一条目录说死、
一条目录说活）：

    XMTcxNjU2Mzk2（目录 N）→ 200，标题《【女流】迷你单机游戏之 阿扎达经典系列第二部》
    XMTcxMzcyMjAw（目录 Y）→ 200，标题《【女流】小型单机游戏之迷画之塔》

两条都在线且标题正确，**条目是对的，目录那一列是旧快照**。条目里
「详情页复核（2026-08-11）……恢复为 alive」的记录与实测一致。

⚠️ 注意优酷对**已失效**视频同样返回 200，所以判活必须看页面标题/`publishTime`，
不能只看状态码。本轮三条都是按标题与 `publishTime` 判定的。

本轮**没有**去改目录那一列：它是当初的采集原始输出，改了就丢掉「当时抓到什么」
这个证据。要用它判断可用性的人，请以条目里的 source status 为准。

## 五、封面

三条的封面都是从详情页里挑出来的**该视频独有**的那一个 ykimg URL
（页面上有 102 个 ykimg 地址，其中 101 个三条共有，属于页面装饰/推荐位；
每条各自只有 1 个是独有的）。三个都实测 200 且返回 `image/jpeg`。

一开始从页面 JSON 里直接取到的那个 `thumbUrl` 三条完全相同，是占位图，没有采用。

## 六、过程中差点写错的三处

1. **2010 版页面里唯一的日期串 `2010-05-15` 在头像图片 URL 的 `?time=` 参数里**
   （`...?time=2010-05-15+18%3A09%3A11`），那是头像上传时间，不是视频发布时间。
2. **《超级玛丽…》在空间页上被包在 `<div class="entry" play_list='ture'>` 里**，
   旁边写着 `<h6 title="【女流】小游戏专题系列">` 和 `视频:7`，一眼像个 7 集专辑；
   取它自己的详情页才确认是单条视频，那个 h6 是外层专辑容器的名字。
3. **本报告的初版断言这三条「只存在于互联网档案馆快照里」，是错的**——
   当时只依据目录的 `alive=N` 和一次失败的连接就下了结论，没有按标题实测。
   三条都还在线。
