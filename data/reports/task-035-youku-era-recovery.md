# Task 035 · 优酷期失踪视频回收（2026-09-20）

> 三条优酷期视频，**目前只存在于互联网档案馆的快照里**：官方空间早已不对外显示内容，
> 站内没有条目，B 站/A 站也没有任何搬运。本报告把它们的标题、上传者、游戏、时长与
> 可用快照地址固定下来，并说明每一项到底是**已确认**还是**推断**。
>
> ⚠️ **本轮不写入任何 `data/entries/` 条目。** 三条的确切日期都达不到 AGENTS.md 第 47 条
> 「没核实的一律留空」的要求，按「宁可存成线索也不要编一个日期」处理。

## 背景：为什么优酷期特别容易整条消失

`data/accounts.yaml` 的 `youku-official` 已记录：`i.youku.com/nvliu66` 现在 302 跳到新主页
系统，显示 **0 视频 0 粉丝**，早期内容完全不在公开页上。也就是说优酷期不像斗鱼期那样
有「录像小屋」这种完整搬运号兜底——**原始页面一旦失效，这条视频在公开网络上就没有
任何副本了**。本轮三条全部属于这种状态：B 站按标题检索均无对应搬运（检索记录见文末）。

## 方法：用优酷 vid 给视频定序

优酷的 `v_show/id_XXXX` 里的 `XXXX` 是 `"X" + base64(纯数字 id)`，例如

    XMTcxMzcyMjAw → base64 解 → 171372200 → 2010-05-08（首条视频《迷画之塔》）
    XODc4ODk2NTY4 → base64 解 → 878896568 → 2015-01-24

这个数字 id 随上传时间单调递增。**在本仓已定日期的 80 条优酷条目上实测：79 对相邻样本
全部顺序一致，0 处逆序。** 所以它可以用来给一条未定日期的视频**卡出区间**——
注意它只能卡区间，不能给出具体某一天，下面每条都按这个限度使用。

方法本身还做过一次**预测性验证**：条目 A 的年份是靠这个梯子推出来的，推完之后才发现
它与目录里独立抓到的「07-16」完全吻合（见 A）。

## 要把这三条转成正式条目，还差什么

只差**一个能直接读出发布日期的原始记载**。可能的来源，按性价比排：

1. **她本人的旧网盘/硬盘目录。** `missing-resources.md` 已记 2026-04-06 切片里本人确认
   私人网盘仍有旧文件。文件名或修改时间就能定日。
2. **优酷空间列表页的更多快照。** 本轮只找到 2014-10-30 一次有效抓取；
   若能找到 2010—2011 年的列表页快照，列表页是直接带发布日期的。
3. **优酷开放 API。** `openapi.youku.com/v2/videos/show.json` 需要 client_id，本轮没有。
4. **第三方旧索引站**（如当年的视频聚合/排行站）对这三个 vid 的收录记录。

## 顺带修正一处目录缺陷

`data/catalogs/youku-video-era.csv` 第 2 行（条目 A）的 date 字段是 `07-16 20:52`，
与全表其余 80 行的 `YYYY-MM-DD` 格式不一致，也是它一直没能进条目的直接原因。
本轮**不改这一行的原始值**（那是实测抓取结果，改了就丢证据），只在本报告里说明它的含义。

条目 B、C 已追加进同一份目录，**date / alive / upload_datetime 三列一律留空**——
这三项都没核实到，按 AGENTS.md 第 47 条留空而不是填推测值；只写了确认到的
标题、vid、url，以及 B 的实测时长 `PT20M36S`。`alive` 留空不代表「不可用」，
而是「本轮没能可靠判定」：优酷对已失效视频同样返回 200，单看状态码判不出来。
