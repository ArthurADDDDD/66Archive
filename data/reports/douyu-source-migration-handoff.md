# 「仅斗鱼来源」补源工作交接

> 整理日期：2026-09-10
>
> 用途：把「把只挂得出斗鱼回放的场次换成主流平台备份」这件事的**当前进度、判定口径、已用尽的路子和剩余缺口**固定下来，供后续接手者直接续做，不必从头摸索。
>
> 背景：斗鱼不是长期视频托管平台，主播回放的保存期限由平台决定，随时可能被清理。因此「某一场只有斗鱼链接」被当成一类需要主动消除的风险。

## 1. 判定口径（续做时请沿用）

来源排序只按覆盖范围定，不按平台：

| 情形 | 处理 |
|---|---|
| 非斗鱼录像时长 **≥ 条目 `duration_min`**，且日期／房间标题／开播时刻能对上 | 排到 `sources` **首位**，斗鱼保留在后作备选（**不删**） |
| 明显短于条目时长 | 只作**补充来源**追加在斗鱼**之后**，`note` 写清缺多少、缺在哪一段 |
| 覆盖不足约四成的碎片、他人机位、归属未定 | **不写入 `sources`**，只记录在调查文档 |

最后一条是为了不让「有非斗鱼备份」这个数字虚高——一个 13 分钟的片段不构成对 5 小时直播的替代。

其他硬性约束：

- 条目的 `date`、`duration_min`、`platform`、稳定 id、`confidence` **不因补源而改动**。发现对不上要单独记为待核问题，不顺手改。
- `status: alive` 只表示公开接口可访问，**不表示逐 P 播放过**。每条新来源的 `note` 都要保留「未逐P验证播放与完整性」这类限制说明。
- 不下载视频。本仓只存元数据与外链。
- 数据改动与文档改动分批提交。

## 3. 怎么拉目录（这是最容易踩坑的部分）

**结论：需要人类先在 Claude 内置浏览器里登录 B 站，之后 `x/space/wbi/arc/search` 可以正常分页。** 匿名态一律返回风控 HTML。登录后**不需要**去抄页面真实请求里的 `dm_img_str` / `dm_img_inter`，自己实现 MD5、从 `x/web-interface/nav` 取 wbi 密钥算 mixin key 签名即可，`dm_img_*` 传固定占位值也能过。

必须知道的四件事：

1. **风控会让接口改返回 HTML 而不是 JSON**，且不报错。取数前要显式判断响应是否以 `<` 开头，否则只会看到一个莫名其妙的 JSON 解析异常。
2. **不被拦的节奏**：`ps=30`（和网页一致，别贪 50）、每页随机 sleep 3~6 秒、每次工具调用只翻 4~5 页（浏览器 JS 工具有 45 秒上限）。按这个节奏翻了约 1400 页零拦截。**被拦之后换 IP 立刻恢复**，干等很慢。
3. **页面一旦导航或重载，注入的函数和已取数据全部清空**。全程留在同一页，每枚举完一个号立刻把数据吐出来落盘，不要攒着。
4. **大输出**：JS 工具返回超限时会自动落到文件并给出路径，但阈值较高（约 19KB 的 JSON 仍内联返回，白烧上下文）。要落盘就一次性把多个号合并输出凑够量。落盘文件是 `[{type,text}]` 包装，且 `JSON.stringify` 的结果解出来是**字符串**，要 `raw_decode` 之后再 `json.loads` 一次。

另外两个已验证的负面结论，别再重复试：

- **给 `arc/search` 传 `keyword` 无效**，会被忽略、照样返回全量。要定位某个时间段就用**二分翻页**：结果按投稿时间倒序，先探几页看日期范围，再定向枚举那一段（对 5045 条的号只翻了 35 页就拿到目标区间）。
- **公开搜索接口（`x/web-interface/search/type`）召回极差**，只能当补充。对秘密录像屋只捞到 75 条，空间接口一拉是 548 条。搜索结果标题还带 `<em>` 高亮标签，判断命中前要先剥标签。
- **gameinns.com（游戏社）不是独立备份**：它是斗鱼 VOD 的镜像索引，页面标「来源：斗鱼」并提供跳回斗鱼的 outbound 链接，站内无自有播放器。底层仍依赖斗鱼，斗鱼清理后跟着失效，**不能当替代源**。2026-09-10 已核实，别再拿它挖。

**交叉比对的铁律**：列表里的投稿时间是**投稿日不是直播日**，多数录播次日凌晨才传，跨日很常见。直播日期一律从**标题**里取。

**相邻日同款 ≠ 同一场（已核实，别再试）**：同一款游戏连打几天很常见，而斗鱼回放是**当天播当天传**（条目日期可信）。实测把 79 条对目录放开到 ±1 天后出现大量「同款相邻日」，逐一拿斗鱼源复核（如 Green Hell 09-28/29/30/10-01 四条独立回放 308/387/386/293，录像小屋只录了 28、30，29 与 10-01 是真缺口），结论是它们都是**连播的不同场次**，不是同一天的错标。所以只按**精确同日**做交叉比对是对的，不要用「错一天=漏网」去松绑。

## 7. 下一步建议

按性价比排序：

1. **找 2021 年到 2022 年前段的搬运号**（38 条，最大空白）。秘密录像屋止于 2021-02，KassyTan 始于 2022-12，中间近 22 个月没有任何已登记的号覆盖。已用每一场的斗鱼房间标题（「瓦西子赤木都给我来」「艾尔登法环Day2一起来吧」等 27 个特征短语）逐条搜过，**零命中**——所以这段缺的是**尚未被发现的账号**，换关键词没有用。可行方向：从这一时期女流相关视频的评论区、合集、关注列表里找录播号；或直接向观众征集。
2. **2019 年 1—11 月（39 条）**。早于秘密录像屋开始投稿（2019-12-02），仓储员同期只有碎片，录像小屋无同日录像。同样需要新账号线索，或 A 站／网盘方向。
3. **处理第 5 节那 6 条碎片**，决定挂不挂。
4. **逐 P 播放抽验**已置前的 64 条。目前全部只做了元数据核对，没有一条验证过实际可播和末尾完整。这是当前数据里最大的一处「未验证」。
5. **第 6 节的待核问题**逐条查证。

## 8. 复用现成的东西

- 交叉比对脚本思路：读 `data/catalogs/*.csv` → 从标题提直播日期 → 与 `data/entries/*.yaml` 按日期 join → 排除 `sources` 里已出现的 BV。
- 写入 `sources` 时 `parts` 必须与 `part_details` 数量一致（`src/lib/schema.ts` 有校验），分P 页码不能重复。
- 每批改完跑 `npm run validate`。当前基线只有一条既有提醒：标签「语音直播」未被使用。
