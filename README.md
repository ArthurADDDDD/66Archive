# 66Archive · 女流66 网络生涯档案

**女流66（石悦）从 2010 年至今的视频、直播与相关资料索引。**

网站：**https://nvliu.wiki/**

> **最后更新：2026-09-02**  
> **当前阶段：补档 / 考据 / 来源复核 / 数据质量维护**

66Archive 是一个持续整理中的民间资料项目，不代表女流66本人或相关平台的官方档案。

**只索引，不搬运。** 仓库和网站不保存直播、视频本体；可播放内容尽量链接回原平台、原投稿或仍可访问的录播来源。

## 当前状态

截至 2026-09-02，网站的主要产品功能已经基本收口：时间线、故事模式、Highlights、游戏 / 节目聚合、数据统计、画廊、协作校对、资料纠错与来源追溯均已进入日常使用阶段。

项目现在的默认目标已经从“继续扩功能”转为**把档案本身补得更完整、更可靠、更可追溯**。后续工作优先放在旧录像补档、历史事件考据、来源复核、标签 / 时长 / 标题修正和视觉资料补充；除明确的 bug、性能 / 兼容性 / 安全问题，或维护者明确提出的新需求外，不主动扩充产品面。

当前阶段和维护口径详见 [`docs/project-status.md`](docs/project-status.md)。

## 网站里有什么

- **编年史 / 故事模式**：按日期浏览已经确认的视频、直播和重要事件，并从完整时间线中抽出阶段性节点；
- **Highlights**：整理比较有代表性的节目、事件、梗和名场面；
- **游戏 / 节目**：把时间线重新按游戏和长期栏目聚合；
- **数据统计**：从现有档案计算直播记录、已确认时长、年度分布等，并展示当前仍然存在的资料缺口；
- **画廊**：保存与时间线相关的图片、截图、周年资料和其他视觉记录；
- **协作校对**：编年史条目里可以直接核对游戏标签并搜索完整游戏词库；“联系我们”可以提交资料纠错，首页“直播间梗”也可以补充线索。无需注册，所有反馈都会人工复核，不会自动改写档案；
- **来源索引**：尽量保留原始页面、录播、目录和调查记录，让每条资料都可以继续追溯。

主要数据位于：

- [`data/entries/`](data/entries/)：时间线主体；
- [`data/games.yaml`](data/games.yaml)：游戏档案；
- [`data/series.yaml`](data/series.yaml)：节目 / 系列；
- [`data/tags.yaml`](data/tags.yaml)：受控内容标签；
- [`data/accounts.yaml`](data/accounts.yaml)：相关账号与来源；
- [`data/catalogs/`](data/catalogs/)：采集过程中保留的原始目录；
- [`data/reports/`](data/reports/)：缺口调查、来源审计和修正记录。

网站前端也公开在这个仓库中，欢迎查看、改进或提交 PR。生产运维配置、后台内部实现和凭据不属于这个公开仓库的内容。

## 优先事项：把「只有斗鱼源」的场次换成主流平台

斗鱼不是长期视频托管平台，主播回放的保存期限由平台决定，**随时可能被清理**。因此本项目把「某一场只挂得出斗鱼回放链接」当成一类需要主动消除的风险，处理原则是：

- 只要找到同一场、覆盖范围明确的非斗鱼录播（B 站 / A 站等），就把它排在 `sources` 首位，**斗鱼回放保留在后面作备选**，不删除；
- 覆盖不全、归属未确认或属于他人机位的录像，只作补充来源追加在斗鱼之后，并在 `note` 里写清缺口，不冒充整场替代；
- 已确认的替换会记录候选 URL、分 P 标题和时长，元数据可访问不等于逐 P 播放过，两者在备注里分开写。

当前进度（2026-09-10）：含斗鱼链接的档案 157 条，其中**仅有斗鱼来源的从 153 条降到 79 条**——64 条已经把非斗鱼录播排在首位，另有 14 条拿到了非斗鱼备份但因覆盖不足或归属存疑，仍以斗鱼为首选。已确认的主要替代来源是 B 站「[女流录像小屋](https://space.bilibili.com/29418340)」、已注销的「秘密录像屋」（UID 28047516，覆盖 2019-12 至 2021-02）、「[KassyTan](https://space.bilibili.com/30032863)」（覆盖 2022-12 至 2023-07，近乎逐日）与「[Zytau](https://space.bilibili.com/35246867)」。

剩下的 79 条集中在两段：**2019 年 1—11 月（39 条）** 和 **2021 年全年到 2022 年前段（38 条）**。后一段是最大的空白——秘密录像屋止于 2021-02，KassyTan 始于 2022-12，中间近 22 个月没有任何已登记的搬运号覆盖；已按每一场的斗鱼房间标题逐条检索过，零命中。这段缺的是**尚未被发现的搬运号**，不是换个关键词就能解决的。

**这也是目前最欢迎的一类线索**：如果你知道某一场斗鱼直播在 B 站 / A 站 / 网盘还有别人录的版本，请提供链接和覆盖时段。逐条清单与排除理由见 [`docs/research/2026-09-09-douyu-alternative-sources.md`](docs/research/2026-09-09-douyu-alternative-sources.md) 及同目录 CSV；进度、判定口径与后续待办见 [`data/reports/douyu-source-migration-handoff.md`](data/reports/douyu-source-migration-handoff.md)。

## 补档阶段的维护重点

下面是已经确认值得继续做、但不一定在当前一轮马上完成的事项。现在默认优先级是**资料完整度和可核验性高于新增页面或新增交互**：

- [ ] **2017 / 2018 年报结构化审计**：把鱼吧年度总结中的直播天数、游戏数、弹幕、砒霜邮件、重大事件等作为 `reported` 历史数据保存，并与当前档案的 `derived` 结果分开；详见 [`annual-report-2017-2018-audit-handoff.md`](data/reports/annual-report-2017-2018-audit-handoff.md)。
- [ ] **心灵砒霜统计双口径**：区分“栏目相关内容条目数”和“真实直播场次数”，避免切片 / `video` 被误写成“直播了一期”。
- [ ] **追查 2018-08-10 大周 MC 第四季**：年报明确写有该节点，而当前第四目现存记录从“第四天”开始；重点寻找第一、二、三天的真实录像或鱼吧 / 开播记录，禁止仅按日期倒推。
- [ ] **补年度大事件的历史语义**：优先检查已有直播条目是否缺少“首次吃鸡、200T 鱼丸、关注 200W、首位皇帝、首次语音直播、主机板块第 1 名”等 `note` / Chronicle 信息。
- [ ] **保存年报原始来源信息**：若找回原鱼吧帖子，补原帖 URL、发布时间、原图索引 / hash 和制作说明。
- [ ] **年报独立页面（暂缓）**：保留“按年份展示年度统计 / 年度大事件 / 年度游戏盘点”的产品想法；当前先做好数据层和来源层，不急着增加新页面。

> 年报里的年度总时长和单日分钟数只作为参考校验，不作为逐场数据的硬对齐条件。录播往往保留完整开播过程，而年度总结可能采用“正式开始”等不同统计口径。

## 目前最需要帮助的地方

这个项目现在最缺的不是“把数字补满”，而是**能够核验的旧资料和来源**。如果你手里有下面这些东西，会非常有帮助：

- **2015 年 5 月直播资料**：2015-01-21 首次实际开播、2015-04-29“背部直播”和 2015-06-30 早期直播都已经确认；5 月目前仍缺可靠直播录像或强开播证据；
- **2015—2017 年初的旧直播录像 / 目录**：这一阶段仍存在明显的历史缺口，公开网络上的现存录像无法完整覆盖；
- **2017 年缺失直播日线索**：现有档案已经比较密集，但和年度直播日外部锚点相比仍可能存在少量缺日；
- **视频时代的旧优酷 / 网盘备份**：部分早期投稿已经失效，只能通过目录、重传或残留记录确认；
- **旧截图、周年视频、粉丝图与画廊资料**：最好能够同时提供大概年份、原始出处或可以帮助定位时间的信息；
- **仅存斗鱼回放场次的其他录像**：见上一节，这是当前风险最高的一类缺口，任何同场的 B 站 / A 站 / 网盘备份都欢迎；
- **纠错与补来源**：如果你发现日期、标题、时长、游戏 / 节目标签、来源链接有误或失效，也欢迎指出。

当前长期缺口、已解决项目与历史调查记录见：[`data/reports/missing-resources.md`](data/reports/missing-resources.md)。网站的**数据统计**页也会按当前 `data/entries/` 动态展示缺口概览。

## 怎么帮忙

现在有几种方式可以直接参与：

- 在**编年史**对应条目的展开区域里核对游戏标签；看过原片后，可以直接从完整游戏词库里搜索并提交判断；
- 在网站的**“联系我们”**页面直接提交日期、标题、时长、来源等纠错；首页**“直播间梗”**区域也可以补充梗和名场面线索；
- 也可以继续通过 GitHub 提交 **Issue / Pull Request**。

网站内提交无需注册，只会作为待复核线索；**任何反馈都需要人工核对后才会进入档案，不会自动写回 `data/**`。**

如果是补档，最好附上能够核验的信息，例如：

- 原视频 / 录播链接；
- BV / AV / AcFun / YouTube / 斗鱼回放 ID；
- 原始标题、上传时间、直播日期；
- 截图、水印、评论区时间线索；
- 旧网盘、硬盘目录或直播日历。

证据不足的内容不会为了补齐时间线而强行写入；能够确认多少，就记录多少。
