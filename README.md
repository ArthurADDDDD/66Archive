# 66Archive · 女流66 网络生涯编年史

**女流66（石悦）从 2010 年至今的视频与直播资料索引。**

网站：**https://i6i6.space/**

这个仓库公开的主要目的，是**分享、留档与让资料来源可追溯**。它不是一个面向部署或二次开发的软件模板，因此 README 不提供本地运行、部署或开发教程。

**只索引，不搬运。** 仓库和网站不保存直播、视频本体；可播放内容尽量链接回原平台、原投稿或仍可访问的录播来源。

## 页面构成

### 首页

首页不是完整目录，而是一条经过整理的入口：

- **ACT I / II / III**：把 2010 至今的网络生涯拆成三个阶段呈现；
- **Highlights**：挑出一些值得单独记住的事件、节目和名场面；
- **随机一晚 / 今日今夕**：从档案里重新打开某一天；
- **游戏预览**：按已收录场次与时长聚合部分长期游玩的游戏；
- **四个房间**：通往不同类型内容的快捷入口；
- **总览统计**：展示目前档案累计出的记录与时长。

### 编年史

完整时间线。按日期浏览已经确认的视频、直播与特殊事件，并进入单条记录查看标题、时长、游戏、节目、来源链接等信息。

### 游戏

把时间线中的游戏记录重新聚合，查看某个游戏出现过多少次、累计多久、最早与最后一次出现在哪一年。

### 节目

整理长期栏目与系列，例如《心灵砒霜》等，并按期数与年份查看。

### 数据

从当前档案实时计算直播条目、已确认时长、年度分布、游戏时长、长期节目等统计。**精确的最新数字以这个页面为准**，README 只保留不容易因一次补档就过期的量级说明。

### 画廊

收录与时间线相关的图片、截图和视觉资料。

### 联系我们

用于提交纠错、补档线索或新的可靠来源。

## 我们收集了什么

目前档案覆盖 **2010 年至今**，包括视频时期、斗鱼直播时期、停播过渡期以及抖音直播时期。

当前已经整理到的规模为：

- **2,700+ 条直播记录**；
- **10,700+ 小时已确认直播时长**；
- 2010 年以来的视频投稿、直播日期、标题、时长、游戏 / 内容标签、节目归属；
- 优酷、哔哩哔哩、AcFun、YouTube、斗鱼、抖音等平台上的原始页面或录播来源；
- 游戏、系列节目、账号与来源档案；
- 为考古保留的原始目录、候选数据和审计报告。

主要数据目录：

- [`data/entries/`](data/entries/)：时间线主体；
- [`data/games.yaml`](data/games.yaml)：游戏档案；
- [`data/series.yaml`](data/series.yaml)：节目 / 系列；
- [`data/accounts.yaml`](data/accounts.yaml)：相关账号与来源；
- [`data/catalogs/`](data/catalogs/)：采集过程中保留的原始目录；
- [`data/reports/`](data/reports/)：缺口调查、来源审计和数据修正记录。

2026 年 8 月，我们重新系统核对了斗鱼官方直播回看。仅这一轮就找回了 **100 个此前未进入档案的直播日**，并用斗鱼官方回放重新校正了大量已有日期的直播时长。2019 年此前最明显的一段缺口因此得到大幅补全。

## 目前仍然存在的缺口

这个档案不会为了“看起来完整”而补数字。找不到可靠证据的地方会直接保留为空缺。

当前最主要的历史缺口包括：

- **2015 年早期**：直播档案仍然结构性稀疏。2015-01-01 至 01-20 是否已经开播尚无法确认；4 月存在录像但具体日期无法定位；5 月及部分月份仍缺少可靠记录。
- **2015—2017 年初**：公开可找到的录像无法完整覆盖当时已经发生的累计直播量，早期仍有一部分直播很可能已经历史遗失。
- **2017 年**：与外部年度直播日锚点相比，目前仍约有数个直播日无法定位。
- **2020 年**：仍有几天可以确认开播、但至今没有找到完整录像，包括 `2020-03-05`、`2020-08-18`、`2020-09-21`、`2020-10-03`；官方回放校正已经缩小年度时长差距，但仍不能认为完全补齐。
- **视频时代**：部分旧优酷页面已经失效，部分作品只能通过目录、重传或其他残留记录确认。
- **2022 年以后**：目前没有发现同等级的大块结构性缺失，但个别日期、标题、游戏标签和时长仍会继续修正。
- **2026 年**：仍在持续更新，不作为历史缺口统计。

更详细、包含已调查来源与所需补档证据的清单见：[`data/reports/missing-resources.md`](data/reports/missing-resources.md)。

## 统计口径与来源

### 什么叫“已收录”

所有站内统计都从 [`data/entries/`](data/entries/) 中的实际条目计算，不使用人为填写的展示数字。

- **直播记录**：`type = live` 的条目数。同一天可能存在两场独立直播，因此“直播记录数”不等于“直播天数”。
- **直播日**：对 `type = live` 的日期去重后得到的天数。
- **已确认时长**：只累加已经有可靠依据的 `duration_min`；未知时长不估算、不补平均值。
- **实际累计时长**：可能高于“已确认时长”。采访、年度日志等外部数字只用于判断档案是否存在缺口，**不会直接写进已确认时长**。
- **游戏 / 节目统计**：只依据已经映射到具体条目的 `games`、`series`、`tags` 等字段计算。

### 来源优先级

资料来源大致按以下顺序使用：

1. **原平台 / 官方记录**：原始投稿、斗鱼官方直播回看、平台详情页等；
2. **完整录播**：哔哩哔哩、AcFun、YouTube 等仍可核验的完整搬运或补档；
3. **目录与日志**：旧投稿目录、贴吧直播日志、标题、上传记录等，用于确认日期与内容；
4. **外部硬锚点**：公开采访、年度直播日志等，用于审计“现有档案是否合理完整”。

当不同来源冲突时，优先采用**更接近原始直播的一手证据**。例如斗鱼接口日期与详情页明确写出的直播日期冲突时，以详情页明确日期为准；完整官方回放与残缺搬运时长冲突时，优先采用可确认的完整回放。

同一场直播存在多个来源时尽量合并，不因为“纯净版 / 弹幕版 / 重传版”重复累计；只有确认属于不同场次或不重叠的连续分段时才分别计入。

每条记录还会使用 `confidence` 标注确定性。证据不足时宁可保留 `medium / low` 或空缺，也不把推测写成事实。
