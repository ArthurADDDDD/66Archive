# 全量条目清点工具（本地、可复用）

档案里 2600+ 条记录绝大多数是机器 / 半自动补进来的，**从来没有被人从头到尾看过一遍**。
这个工具把每一条摆出来让人逐条确认，并且把「机器觉得这条可能有问题」的排在最前面，
让有限的注意力花在刀刃上。

它**不会碰 `data/**`**。人工判定只写进本地的 `reviews.json`；真正回写档案是最后一步
单独做的，判错了在这个工具里随时改回来，不会污染档案。

跟 [`scripts/calibrate/`](../calibrate/README.md) 是同一套结构（server + 单页 HTML +
局域网访问 + 定期快照），但任务不同：calibrate 是「给一批条目补某个字段」，
这个是「把全部条目核对一遍对不对」。

---

## 怎么跑

```bash
node scripts/audit/server.mjs
```

然后打开 http://localhost:4174（4173 是 calibrate 的端口，两个可以同时开着）。
启动时会打印这一次的条目数与机器自检结果——数据是现读 `data/**`，
永远反映当前真实状态。中途 `data/**` 变了，重启一下即可。

### 从另一台设备（比如 PC）连进来

```bash
HOST=0.0.0.0 node scripts/audit/server.mjs
```

启动日志会打印局域网地址，例如 `http://192.168.x.x:4174`。

⚠️ 这个工具**没有任何登录鉴权**——局域网内任何设备都能连上来改。
只在你信任的家庭 / 办公网络里这样开，不要把这个端口转发到公网。

两台设备一起改是安全的：每次保存都是先读硬盘上最新的 `reviews.json` 再合并这一条，
不是拿内存里的旧快照整份覆盖。左栏进度每 12 秒自动跟服务端同步一次。
每存 25 次，`reviews-backups/` 里会多一份带时间戳的快照。

## 界面分两种模式

**快速清点（列表）** —— 一页 60 条，每条一行摆出日期 / 类型 / 平台 / 时长 /
置信度 / 游戏 / 标签 + 机器自检结论，逐行点 ✓ 或 ✗。
整页都没问题时可以用「这一页 N 条都没问题」一次过掉——
**置信度高、机器也没查出疑点的那一大批就是这样扫的**。

**逐条细看** —— 一次一条，摆出档案里的全部字段、备注、分段、来源链接，
点链接直接去 B 站看原片核对。判定为「有问题」时勾一下**是哪个字段不对**
（日期 / 标题 / 类型 / 平台 / 时长 / 游戏 / 标签 / 系列 / 链接 / 重复 / 其他），
再在备注里写正确的应该是什么。勾了字段我才知道要改哪里。

### 键盘（只在「逐条细看」里生效）

| 键 | 作用 |
|---|---|
| `J` / `K` | 下一条 / 上一条 |
| `A` | 上一条 |
| `S` | 判为「没问题」并跳下一条 |
| `D` | 判为「有问题」并跳下一条 |

## 机器自检：只指出可疑，不下结论

左栏「疑点」筛选可以只看某一档。两档的含义：

- **几乎一定要改（high）** —— 结构性矛盾，基本可以确定是错的：
  没日期 / 没标题 / 日期格式不对 / 日期在未来 / 2015 年前出现 `live` /
  没有任何来源 / 时长为负或超过一天 / 引用了词表里不存在的游戏·系列·账号 /
  标题里写的日期和 `date` 字段对不上 / 分段时间点超过总时长。
- **值得看一眼（medium）** —— 可疑但也可能本来就对，只有人能定：
  直播没时长 / 来源全部失效 / 没有一个来源被确认可用 / 标签不在受控词表 /
  同一天有标题几乎一样的另一条 / 同一个链接挂在多条上（合集跨天是正常的，
  拆错就要改）/ 既没有游戏也没有标签和系列。

**这些规则会误报**，尤其是「同一个链接挂在多条上」和「没有内容标注」这两类。
误报就直接判「没问题」过掉，不用为了迁就机器去改档案。

排序默认就是「疑点重的在前、置信度低的在前、日期新的在前」，
所以一路往下点，最需要判断的永远在最前面。

## 清点完之后：怎么应用回 `data/**`

`reviews.json` 里每条长这样：

```json
{
  "id": "2019-07-13-live-01",
  "verdict": "bad",                       // ok | bad | skip
  "wrong": ["date", "duration"],          // 哪些字段不对
  "note": "日期应该是 07-14，时长是 4 小时不是 40 分钟",
  "title": "…", "date": "…", "file": "data/entries/…"
}
```

把这份文件交给负责数据的角色，按 `verdict: bad` 的条目逐条改 `data/**`，
走仓库现有的暂存 / 落盘机制（见根目录 `AGENTS.md`「改动怎么才能上线」），
不要绕开它直接批量写。改完跑 `npm run validate`。

`verdict: skip`（拿不准）的留到下一轮，或者交给能查证的人；
不要因为「清点要收尾了」就把拿不准的随手判成没问题——那比不判更贵。
